# Техническое задание

## Сервис генерации шапки «Где мы находимся»

Внутренний инструмент редакции. Версия ТЗ **1.3**.

История изменений — раздел 16.

---

## 1. Назначение

Раз в неделю редакция публикует постоянный визуальный элемент — шкалы положения классов активов в годовом диапазоне. Требования к самой картинке заданы разделом 10.1.1 редакционного гайда и в этом документе воспроизведены как жёсткие ограничения.

Сервис нужен, чтобы еженедельная сборка занимала минуты и давала **воспроизводимый** результат: при одинаковых входных файлах картинка должна получаться одинаковой независимо от того, кто и на какой машине её собрал. Это не эстетическое пожелание — элемент выходит еженедельно годами, и дрейф оформления от выпуска к выпуску разрушает его функцию.

**Не является** инструментом построения произвольных графиков. Сервис умеет одну картинку и не должен уметь другие.

### 1.1. Формулировка воспроизводимости

Требование формулируется в сильной форме:

> Одинаковый файл данных + одинаковый файл настроек + один и тот же образ (по digest) = **побайтно идентичный PNG**, на любой машине, в любой день.

Отсюда следуют обязанности, разнесённые дальше по документу: отсутствие внешних входов в рендерере (8.6), поставка шрифтов внутри образа (6.3), фиксация зависимостей по версиям и хешам (11.4), эталонные тесты (13).

## 2. Пользовательский сценарий

1. Аналитик открывает сервис в браузере по адресу в локальной сети.
2. Скачивает шаблон Excel (если заполняет впервые).
3. Загружает заполненный файл с данными по пяти бенчмаркам.
4. Если файл не соответствует спецификации — получает список проблем с указанием ячеек и способа исправления. Исправляет, загружает снова.
5. Загружает сохранённый файл настроек оформления либо выбирает пресет.
6. При необходимости правит оформление в UI, видит результат в реальном времени.
7. Сохраняет настройки в файл, если менял.
8. Нажимает «Скачать PNG», получает файл.

Типичный цикл после первичной настройки — загрузил Excel, скачал PNG. Дата выпуска берётся из файла данных (4.6), поэтому файл настроек от недели к неделе не меняется вовсе.

## 3. Архитектура и стек

**Backend:** Python 3.12, FastAPI, uvicorn.
**Frontend:** JavaScript, любой современный сборщик. SPA, отдаётся тем же контейнером как статика.
**Состояние:** сервис не хранит состояние. Базы данных нет. Данные и настройки живут в памяти вкладки браузера и в файлах у пользователя.

### 3.1. Где происходит отрисовка

**Превью и итоговый файл — это один и тот же PNG.**

Схема:

1. Frontend отправляет на бэкенд данные и настройки.
2. Backend собирает SVG по шаблону, растрирует его в PNG и возвращает PNG.
3. Frontend показывает этот PNG как превью, масштабируя средствами CSS под окно.
4. При нажатии «Скачать PNG» frontend сохраняет **уже полученный байтовый массив**. Повторного запроса к бэкенду нет.

Смысл решения: совпадение превью и результата не проверяется на приёмке, а обеспечивается конструкцией — это физически один файл. Вместе с этим отпадают вопросы о согласовании браузерного и серверного текстового рендеринга, о встраивании шрифтов в каждый ответ превью и о выборе между двумя движками растеризации.

Отрисовка на фронте (`canvas.toBlob`, SVG в DOM) **запрещена**: шрифты в этом случае берутся из операционной системы пользователя, и картинка у разных сотрудников получится разной.

SVG как промежуточное представление сохраняется — он удобен для отладки, для эталонных тестов (13) и отдаётся отдельной кнопкой (9).

### 3.2. Растеризация

**resvg**, вызывается как CLI-бинарник через `subprocess`.

- Версия бинарника и его `sha256` зафиксированы в репозитории; бинарник либо вендорится в репозиторий, либо тянется при сборке с внутреннего зеркала с проверкой хеша.
- Запуск обязан отключать системные шрифты и указывать каталог со вшитыми шрифтами явно (в текущей версии resvg — `--skip-system-fonts` и `--use-fonts-dir`; точные флаги проверить на зафиксированной версии). Если растеризатор способен подобрать шрифт из системы — воспроизводимость не гарантируется.
- Chromium/Playwright **не используются**. Образ легче примерно на 1 ГБ, нет жизненного цикла браузера, нет отдельного канала скачивания браузера при сборке (см. 11.4).

### 3.3. Обработка Excel

`openpyxl`, режим `data_only=True`, `read_only=True`. Чтение только; запись — исключительно для генерации файла-шаблона. Особенности работы с кэшем формул — см. 5.1.

## 4. Спецификация файла данных

### 4.1. Общие требования

- Формат `.xlsx` или `.xlsm`. Форматы `.xls` и `.csv` не поддерживаются.
- Размер файла — не более 2 МБ.
- Обязательный лист с именем `data`. Регистр значим.
- Обязательный лист с именем `meta` (4.6).
- Прочие листы игнорируются.
- Строка 1 листа `data` — заголовки. Данные начинаются со строки 2.
- Пустая строка внутри блока данных прерывает чтение (см. предупреждение в 5.2).

### 4.2. Столбцы листа `data`

| Столбец | Обязательный | Тип | Правила |
|---|---|---|---|
| `key` | да | строка | Латиница, цифры, подчёркивание. 1–32 символа. Уникален в пределах файла. Используется для привязки индивидуальных настроек строки |
| `label` | да | строка | 1–40 символов. Подпись строки в картинке |
| `unit` | нет | строка | 0–16 символов. Единица измерения, выводится рядом с подписью |
| `min` | да | число | Годовой минимум |
| `max` | да | число | Годовой максимум |
| `current` | да | число | Текущий уровень |
| `prev` | да | число | Уровень неделю назад |
| `decimals` | нет | целое | 0–3. Число знаков после запятой при выводе значений. По умолчанию 0 |
| `inverted` | нет | логический | Истина — показатель инвертирован по смыслу (доходность, премия). Влияет только на сноску, не на геометрию. По умолчанию ложь |

Порядок столбцов в файле произвольный, имена — строго как в таблице.

### 4.3. Нормализация значений при чтении

Применяется до валидации, одинаково ко всем строковым полям:

- Обрезаются ведущие и хвостовые пробельные символы, включая **неразрывный пробел** `U+00A0` и узкий неразрывный `U+202F`. При копировании данных из веб-страниц они прилетают постоянно и без нормализации дают невнятную ошибку «ключ содержит недопустимые символы».
- Внутренние последовательности пробельных символов в `label` и `unit` схлопываются в один обычный пробел.
- Поле `inverted` распознаёт: булев тип Excel, а также строки `TRUE`, `FALSE`, `ИСТИНА`, `ЛОЖЬ`, `да`, `нет`, `1`, `0` в любом регистре. Всё прочее — ошибка.

Числовые значения **не приводятся** из строк ни при каких условиях. Строка «14,2» — это ошибка с подсказкой, а не повод для догадок: молчаливое приведение в публикуемой финансовой графике недопустимо.

### 4.4. Количество строк

От 1 до 8. Рабочее значение — 5. При количестве, отличном от 5, выдаётся предупреждение, но обработка продолжается.

### 4.5. Порядок строк

Порядок строк в картинке соответствует порядку строк в файле. Сервис не сортирует данные самостоятельно ни при каких условиях.

### 4.6. Лист `meta`

Лист из двух столбцов без заголовка: столбец A — ключ, столбец B — значение.

| Ключ | Обязательный | Тип | Смысл |
|---|---|---|---|
| `as_of` | да | дата | Дата актуальности данных |

`as_of` читается как дата Excel либо как строка `ГГГГ-ММ-ДД`. Иные форматы — ошибка с указанием ожидаемого вида.

Значение подставляется в строку источника (6.2, `texts.source`) в виде `ДД.ММ.ГГГГ` и в имя скачиваемого файла в виде `ГГГГ-ММ-ДД`.

Неизвестные ключи на листе `meta` игнорируются с предупреждением.

Почему дата приходит файлом данных, а не берётся из системных часов и не правится руками в JSON: она меняется еженедельно вместе с данными, а файл настроек при этом остаётся неизменным годами. Кроме того, обращение к текущей дате внутри рендерера нарушило бы 1.1 — один и тот же комплект файлов давал бы разные картинки в разные дни.

### 4.7. Файл-шаблон

Сервис отдаёт по запросу готовый `.xlsx` с листами `data` (корректные заголовки и одна строка-пример), `meta` (заполненный `as_of`) и `readme` (описание столбцов и правил). Шаблон генерируется кодом, не хранится как статический файл, чтобы не рассинхронизироваться со спецификацией.

## 5. Валидация данных

Ключевое требование: **сообщение об ошибке должно позволять исправить файл, не обращаясь к разработчику и не открывая эту спецификацию.**

Каждое сообщение содержит: адрес ячейки или столбца, что обнаружено, что ожидалось, как исправить.

### 5.1. Ошибки, блокирующие отрисовку

| Условие | Сообщение (образец) |
|---|---|
| Нет листа `data` | Не найден лист `data`. В файле есть листы: `Лист1`, `расчёт`. Переименуйте нужный лист в `data` |
| Нет листа `meta` или ключа `as_of` | Не найден лист `meta` с ключом `as_of`. Добавьте лист `meta`, в ячейку A1 впишите `as_of`, в B1 — дату актуальности данных. Проще всего скачать шаблон и перенести данные в него |
| Неверный формат `as_of` | Лист `meta`, ячейка B1: значение «12 марта» не распознано как дата. Впишите дату ячейкой формата «Дата» либо текстом вида `2026-03-12` |
| Отсутствует обязательный столбец | Не найден обязательный столбец `prev`. Возможно, имеется в виду столбец `previous` в ячейке E1 — переименуйте его в `prev` |
| Нечисловое значение в числовом поле | Ячейка D4: ожидалось число, найден текст «14,2%». Уберите знак процента и убедитесь, что в ячейке число, а не текст |
| Число сохранено как текст | Ячейка C7: значение выглядит числом, но сохранено как текст. В Excel: выделите столбец → Данные → Текст по столбцам → Готово |
| **Формула без сохранённого результата** | Ячейка D4 содержит формулу `=B4*100`, но её результат в файле не сохранён. Откройте файл в Excel и сохраните ещё раз — либо вставьте в ячейку готовое значение |
| Пустая обязательная ячейка | Ячейка F3 пуста. Для строки `ofz_10y` требуется значение `prev` |
| `min` ≥ `max` | Строка 5 (`brent`): минимум 88 не меньше максимума 62. Вероятно, значения перепутаны местами |
| `current` вне диапазона | Строка 3 (`corp_spread`): текущее значение 540 выше годового максимума 520. Если это новый годовой максимум — укажите в `max` значение 540. Если нет — проверьте, за какой период рассчитан максимум |
| `prev` вне диапазона | Строка 2 (`ofz_10y`): значение недельной давности 13,2 ниже годового минимума 13,8. Проверьте, за какой период рассчитан минимум |
| Дублирующийся `key` | Значение `gold` в столбце `key` встречается дважды: строки 5 и 6. Ключи должны быть уникальны |
| Недопустимый `key` | Ячейка A4: ключ «золото» содержит недопустимые символы. Допустимы латиница, цифры и подчёркивание |
| Недопустимый `decimals` | Ячейка H4: ожидалось целое число от 0 до 3, найдено 2,5 |
| Нераспознанный `inverted` | Ячейка I4: значение «х» не распознано. Допустимы ИСТИНА, ЛОЖЬ, TRUE, FALSE, да, нет, 1, 0 |
| Строк больше 8 | В файле 11 строк данных. Максимум — 8 |
| Нет ни одной строки | Лист `data` не содержит строк с данными |

**Про кэш формул.** `openpyxl` не вычисляет формулы — он читает результат, сохранённый Excel'ом при последнем сохранении файла. Если файл собран скриптом, выгружен из внешней системы или ни разу не открывался в Excel, кэша нет, и все расчётные ячейки читаются как пустые. Без отдельного сообщения аналитик получит «ячейка пуста» на визуально заполненном файле и пойдёт к разработчику, то есть ровно то, что этот раздел запрещает. Реализация обязана различать «пусто» и «формула без кэша»: для этого файл при необходимости открывается вторым проходом с `data_only=False`, чтобы достать текст формулы для сообщения.

### 5.2. Предупреждения, не блокирующие отрисовку

| Условие | Смысл |
|---|---|
| Строк не 5 | Штатная конфигурация — пять классов активов |
| **Данные ниже пустой строки** | Чтение остановлено на строке 7 (пустая). Ниже обнаружены непустые ячейки — они не попали в картинку |
| **Подпись не помещается в колонку** | Подпись строки `imoex_tr` шире колонки подписей (252 px при `labelColumnWidth` 240) и наедет на шкалу. Сократите подпись или увеличьте `labelColumnWidth` |
| **`rowOverrides` ссылается на отсутствующий ключ** | В настройках задано индивидуальное оформление для ключа `gold`, которого нет в файле данных. Проверьте, не переименован ли он |
| `current` равен `prev` | За неделю значение не изменилось — проверьте, не скопирован ли столбец |
| Диапазон уже 1% от текущего значения | Шкала будет визуально вырожденной |
| `current` или `prev` совпадает с границей диапазона | Точка встанет на край шкалы, подпись будет прижата к краю |
| Неизвестные ключи на листе `meta` | Перечисляются, игнорируются |
| **Неизвестный столбец** | Столбец `комментарий` в ячейке H1 не входит в спецификацию и будет проигнорирован. Блокировать отрисовку из-за лишнего столбца с комментарием было бы абсурдом |

Предупреждение «набор ключей отличается от предыдущей загрузки в этой сессии» из версии 1.0 **удалено**: сессия живёт в пределах вкладки, каждую неделю это новая сессия, сравнивать не с чем. Его роль в части отлова опечаток закрывает проверка `rowOverrides`.

### 5.3. Поведение интерфейса

Ошибки и предупреждения показываются единым списком, ошибки первыми. При наличии хотя бы одной ошибки превью не строится, кнопки скачивания недоступны. Предупреждения не блокируют ничего.

Валидация обрабатывает **весь файл целиком** и возвращает все найденные проблемы сразу. Останавливаться на первой ошибке запрещено: это превращает исправление файла в многократный цикл загрузок.

Требование распространяется и на ошибки в заголовках: **пропущенный обязательный столбец не прекращает разбор**. Остальные столбцы читаются, ячейки проверяются, дубли ключей ищутся, диапазон проверяется по тем значениям, которые удалось прочитать. Иначе один переименованный заголовок скрывает все прочие дефекты файла — ровно тот случай, который проверяет критерий приёмки 4.

## 6. Спецификация настроек оформления

### 6.1. Формат

JSON, UTF-8. Загружается и сохраняется как файл через браузер. Серверного хранилища нет.

Обязательное поле `version` (целое). При загрузке файла с неизвестной версией — понятное сообщение, а не падение.

**Единственный источник правды для схемы — модель Pydantic на бэкенде.** Из неё выводятся: значения по умолчанию (`/api/settings/defaults`), валидация (`/api/settings/validate`) и JSON Schema (`/api/settings/schema`), по которой фронтенд строит форму редактирования. Дублировать описание полей в коде фронтенда запрещено — иначе при любой правке схемы форма и валидатор расходятся.

```json
    "legendScale": "шкала — диапазон за 12 месяцев",
    "footnote": "У доходностей и премий выше по шкале — ниже цена бумаги.",
    "source": "Источник: Мосбиржа, расчёты редакции. Данные на {as_of}"
  },
  "toggles": {
    "showTitle": true,
    "showLegend": true,
    "showFootnote": true,
    "showSource": true
  }
}
```

Пояснения к полям, добавленным в 1.1:

- `geometry.labelGap` — зазор между колонкой подписей и началом шкалы; используется в проверке 5.2 на переполнение подписи.
- `geometry.prevStrokeWidth` — толщина кольца точки «неделю назад» (см. 7.4).
- `geometry.titleGap`, `legendGap`, `legendItemGap`, `footnoteGap`, `lineHeight` — вертикальная раскладка. В версии 1.0 задавался только `rowHeight`, из-за чего расстояния между блоками оставались на усмотрение реализации — то есть были не зафиксированы и могли измениться при любой доработке.
- `numberFormat` — см. 7.2.
- `canvas.height`, `geometry.rowHeight` и `labelColumnWidth` подобраны так, чтобы пять штатных строк с заголовком, легендой, сноской и источником занимали холст целиком: требуемая высота — 688 px при заданных 690. Запаса под лишнюю строку текста нет сознательно: поля сверху и снизу остаются симметричными, а при удлинении текстов срабатывает предупреждение 7.7 с точной требуемой высотой.
- `rowOverrides.<key>` — допустимы поля `current`, `prev`, `connector`, `track`. Иные поля отклоняются валидатором.
- `texts.source` — шаблон; плейсхолдер `{as_of}` заменяется датой с листа `meta`. Иные плейсхолдеры не поддерживаются, неизвестная фигурная подстановка — ошибка валидации.

### 6.3. Шрифты

Список доступных семейств отдаётся бэкендом и формируется из шрифтов, вшитых в образ. Произвольный ввод названия шрифта не допускается — он сломает воспроизводимость.

**Поставляются:**

| Семейство | Лицензия | Роль |
|---|---|---|
| **Arimo** | SIL OFL 1.1 | Основное. Метрически совместимо с Arial, кириллица есть |
| **Inter** | SIL OFL 1.1 | Альтернативное |

**Arial поставлять нельзя.** Шрифт принадлежит Monotype, права на распространение внутри контейнера у редакции нет. Если нужен вид Arial — это Arimo: совпадающие метрики, открытая лицензия. Liberation Sans в качестве замены не подходит, несмотря на ту же метрическую совместимость: в нём есть только начертания 400 и 700, а схема типографики использует 400/500/600.

**Шрифты поставляются статическими файлами по одному на начертание** (400, 500, 600). Переменные шрифты не используются — их поддержка в растеризаторе неполна и является лишним источником различий.

Файлы шрифтов лежат в репозитории, а не скачиваются при сборке.

### 6.4. Валидация настроек

При загрузке JSON: проверка версии, типов, диапазонов значений, формата цветов (`#RRGGBB`), существования указанного шрифта и начертаний, корректности плейсхолдеров в `texts`. Сообщения по тому же принципу, что и для Excel — с указанием пути к полю:

> Поле `typography.title.size`: ожидалось число от 8 до 72, получено 0.
> Поле `colors.current`: значение «blue» не является цветом. Ожидается формат `#RRGGBB`.
> Шрифт «Helvetica Neue» недоступен. Доступны: Arimo, Inter.
> Поле `geometry.prevRadius`: значение 6 слишком близко к `currentRadius` 6. Разница должна быть не менее 1,5 px, иначе кольцо «неделю назад» сливается с краем текущей точки.
> Поле `texts.source`: неизвестная подстановка `{date}`. Поддерживается только `{as_of}`.

Отсутствующие необязательные поля добираются из значений по умолчанию. Неизвестные поля игнорируются с предупреждением.

**Файл настроек не меняется от сохранения к сохранению.** Сохранённый и загруженный обратно JSON при повторном сохранении даёт тот же текст. Значения по умолчанию проходят то же приведение типов, что и загруженные: иначе пресет со значением `92` и сохранённый из интерфейса `92.0` описывают одну и ту же картинку разным текстом, и диффы шумят на пустом месте.

**Предупреждения о неразличимых цветах.** Не блокируют отрисовку:

| Условие | Смысл |
|---|---|
| `colors.current` и `colors.prev` слабо различимы | Две точки — единственный носитель смысла картинки |
| Цвет точки слабо отличается от `colors.track` | Точка потеряется на полосе |
| То же для любой строки из `rowOverrides` | Проверяется отдельно по каждой строке |

Мера различимости — ΔE (CIE76) в пространстве Lab, порог 25. Константа задана в коде и настройке не подлежит. Эвристика сознательно грубая: её задача — поймать случайную вставку не того hex, а не судить о вкусе.

### 6.5. Пресеты

Каталог `/presets` монтируется в контейнер томом только на чтение. Файлы `*.json` из него доступны в UI выпадающим списком. Туда кладётся утверждённый редакцией вариант оформления, чтобы все собирали одинаково.

Файл с зарезервированным именем `palette.json` пресетом не считается и в списке не показывается — см. 6.6.

### 6.6. Палитра и ввод цвета

Любое цветовое поле настроек задаётся двумя равноправными способами: выбором из утверждённой палитры и вводом произвольного `#RRGGBB`. Второй способ — не аварийный обход, а штатный: палитра подсказывает, но не ограничивает.

**Источник палитры.** Файл `palette.json` в том же смонтированном каталоге, что и пресеты. Отдаётся эндпоинтом `GET /api/palette`.

```json
{
  "version": 1,
  "colors": [
    { "hex": "#378ADD", "name": "Синий — «сейчас»" },
    { "hex": "#888780", "name": "Серый — «неделю назад»" },
    { "hex": "#F1EFE8", "name": "Песочный — полоса шкалы" },
    { "hex": "#C9A227", "name": "Золото" },
    { "hex": "#111111", "name": "Основной текст" },
    { "hex": "#777777", "name": "Вторичный текст" }
  ]
}
```

`name` обязателен и показывается подсказкой у образца: палитра из полутора десятков безымянных квадратиков не подсказывает ничего.

**Ввод hex.** Поле принимает `#RRGGBB`, `RRGGBB` без решётки и краткую форму `#RGB`, в любом регистре. Значение нормализуется к `#RRGGBB` в верхнем регистре в момент применения — именно оно попадает в настройки и в сохраняемый файл.

Формат `#RRGGBBAA` и именованные цвета CSS не поддерживаются: прозрачность задаётся только флагом `canvas.transparent`, а имена цветов лишают запись однозначности.

Некорректный ввод не применяется — поле подсвечивается, в настройках остаётся прежнее значение, запрос на отрисовку не уходит. Пустое поле трактуется как незавершённый ввод, а не как сброс.

Послабления при вводе действуют **только в интерфейсе**. В файле настроек формат остаётся строгим `#RRGGBB` (6.4): файл читает не только человек, и разнобой в записи цвета превращается в разнобой в диффах.

**Отказоустойчивость.** Файл отсутствует, повреждён или не прошёл валидацию — сервис поднимается на встроенной палитре по умолчанию, пишет причину в лог и возвращает её в ответе эндпоинта, чтобы UI показал предупреждение. Падать при этом сервис не имеет права: палитра — удобство, а не условие работы.

**Палитра не является входом рендерера.** В настройках и в запросе на отрисовку всегда лежит конкретный `#RRGGBB`; подмена `palette.json` не меняет ни одной уже собранной картинки и не может изменить результат повторной сборки из тех же файлов. Поэтому палитру можно править, не сверяясь с выпусками прошлых недель.

**Палитра не редактируется из интерфейса.** Это утверждённый редакцией набор, он правится файлом — как и пресеты.

## 7. Правила отрисовки

### 7.1. Измерение текста

SVG не умеет ни переносить текст по словам, ни сообщать ширину строки. При этом от рендерера требуется прижимать подписи к краю (7.5), переносить сноску и источник (7.6) и предупреждать о переполнении колонки подписей (5.2). Всё это требует измерения ширины строки на бэкенде.

**Ширина строки вычисляется по метрикам шрифта средствами `fontTools`:** сумма горизонтальных ширин глиссов с учётом кернинга, масштабированная на кегль. Результат детерминирован и не зависит от окружения.

Растеризатор выполняет собственный шейпинг и может применить кернинг из GPOS, которого в измерении нет. На латинице и кириллице расхождение не превышает долей процента, и измерение влияет только на решения раскладки — где разорвать строку, прижать ли подпись к краю — но не на итоговое положение текста: центрирование выполняет сам растеризатор через `text-anchor`. Поэтому при проверках «помещается ли» используется запас 1,5 %.

`<foreignObject>` для переноса текста **запрещён** (8.4).

### 7.2. Форматирование чисел

Единое для всех чисел на картинке — подписи значений и подписи концов шкалы.

- Округление до `decimals` знаков выполняется через `decimal.Decimal` с режимом `ROUND_HALF_UP`. Встроенный `round()` использовать запрещено: он реализует банковское округление, и `round(0.5)` даёт `0`. Для публикуемых цифр это недопустимо.
- Дробная часть выводится всегда в количестве `decimals` знаков, включая незначащие нули: при `decimals: 2` значение 13,5 печатается как `13,50`.
- Разделитель дробной части — `numberFormat.decimalSeparator`, по умолчанию запятая.
- Разделитель разрядов — `numberFormat.thousandsSeparator`, по умолчанию неразрывный пробел `U+00A0`. Допустимые значения: `""`, `U+00A0`, `U+2009`.
- Знак минуса — `numberFormat.minusSign`, по умолчанию `U+2212` (типографский минус, а не дефис).
- Единица измерения отделяется от числа символом `numberFormat.unitSeparator`, по умолчанию неразрывным пробелом.
- Дата `as_of` выводится в формате `ДД.ММ.ГГГГ`. Настройке не подлежит.

### 7.3. Геометрия

Шкала строки — горизонтальная полоса от `padding.left + labelColumnWidth` до `canvas.width − padding.right`. Длина одинакова для всех строк.

Положение точки: `x = trackStart + (value − min) / (max − min) × trackWidth`.

Подпись строки — слева, по левому краю, вертикально по центру относительно шкалы. Единица измерения добавляется к подписи.

Значения минимума и максимума подписываются под концами шкалы: минимум по левому краю, максимум по правому.

Текущее значение подписывается над текущей точкой, выравнивание по центру точки.

**Вертикальная раскладка**, сверху вниз, каждый блок — только если включён соответствующий переключатель:

```
padding.top
заголовок
titleGap
строки данных (rowHeight каждая)
legendGap
легенда
footnoteGap
сноска (с переносами)
footnoteGap
источник (с переносами)
padding.bottom
```

Высота строки текста = `size × lineHeight`.

### 7.4. Точки «сейчас» и «неделю назад»

- Текущая точка — заливка `colors.current`, радиус `currentRadius`, без обводки.
- Точка «неделю назад» — **кольцо**: без заливки, обводка `colors.prev` толщиной `prevStrokeWidth`, радиус `prevRadius`.

**Порядок наложения снизу вверх:** полоса шкалы → соединительная линия → текущая точка → кольцо «неделю назад» → подписи.

Кольцо рисуется **поверх** текущей точки. Это решает случай совпадения значений: при `current == prev` кольцо видно поверх заполненной точки как контрастный контур внутри неё. Обратный порядок (как было в версии 1.0) при `prevRadius < currentRadius` делает точку «неделю назад» полностью невидимой.

Поскольку кольцо полое, рисование поверх не скрывает текущую точку и не нарушает смысловую иерархию: основной элемент остаётся крупнее и плотнее.

### 7.5. Крайние случаи

**Подпись значения выходит за холст.** Если точка близка к краю шкалы, подпись прижимается к границе: `text-anchor` меняется на `start` или `end` соответственно. Факт выхода определяется измерением (7.1). Обрезка подписи не допускается ни при каких условиях.

Границами служат концы шкалы, а не края холста. При `current == min` подпись, прижатая к левому полю холста, наехала бы на колонку подписей строк.

**Точки перекрываются.** Если расстояние между центрами меньше `currentRadius + prevRadius`, соединительная линия не рисуется. Обе точки при этом остаются на холсте и различимы за счёт правила 7.4.

**Значения совпадают.** При `current == prev` линия не рисуется, центры совпадают, кольцо видно поверх заполненной точки.

**Вырожденный диапазон.** При `min == max` валидация выдаёт ошибку. Случай до отрисовки не доходит.

### 7.6. Легенда и подписи

Легенда — под блоком строк, включает образцы обеих точек (заполненная и кольцо, в том же оформлении, что и на шкалах) с подписями и пояснение про шкалу. Элементы легенды разделены `legendItemGap`.

Сноска и строка источника — ниже легенды, каждая отдельным блоком. Перенос по словам выполняется по ширине области отрисовки на основании измерения (7.1). Перенос по символам внутри слова не выполняется; слово, не помещающееся целиком, выступает за границу с предупреждением.

### 7.7. Высота холста

Если заданной высоты не хватает для размещения всех элементов, выдаётся предупреждение с указанием требуемой высоты. Автоматическое сжатие элементов запрещено — оно ломает единообразие между выпусками.

## 8. Жёсткие ограничения визуала и реализации

Раздел обязателен к исполнению. Перечисленное не должно появиться ни в коде, ни в настройках, ни как «улучшение».

**8.1. Точка «неделю назад» не отключается.** Настройками можно изменить её цвет, радиус и толщину. Скрыть — нельзя. Флага `showPrev` в схеме настроек нет и не должно появиться. Это главный смысловой элемент картинки; без него она превращается в обычный индикатор.

**8.2. Полоса шкалы — сплошная заливка одним нейтральным цветом.** Запрещены: градиенты, деление на зоны, цветовое кодирование «хорошо/плохо», окраска в зависимости от положения точки.

**8.3. Никаких стрелок, знаков «плюс/минус», процентов изменения на картинке.** Направление недельного хода показывается только положением двух точек.

**8.4. Запрещённые элементы SVG:** `<foreignObject>`, `<image>` с внешними ссылками, `<script>`, CSS-анимации и `<animate>`, фильтры, ссылки на внешние шрифты по URL.

`<foreignObject>` вынесен в запреты отдельно: это единственный способ получить автоматический перенос текста средствами браузера, и разработчик потянется к нему при чтении 7.6. resvg его не поддерживает вообще — картинка молча потеряет сноску и источник.

**8.5. Шкала жёстко равна диапазону `min…max`.** Никакого зума, отступов от границ, «красивого» округления границ, автоматического расширения диапазона. Границы берутся из файла как есть.

**8.6. В рендерере нет внешних входов.** Запрещены обращения к `datetime.now()`, системной локали, переменным окружения, случайным числам, файловой системе за пределами каталога шрифтов и системным шрифтам. Всё, что попадает в картинку, приходит во входных данных. Это техническая формулировка требования 1.1.

Палитра (6.6) в рендерер не передаётся и на результат не влияет: к моменту отрисовки цвет — это уже конкретный `#RRGGBB` в настройках.

**8.7. Порядок строк не изменяется** ни сортировкой, ни настройками. Только порядок в файле.

**8.8. Никаких анимаций** в превью и, разумеется, в PNG.

## 9. API

Все эндпоинты под префиксом `/api`. Ответы — JSON, кроме бинарных.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка живости |
| GET | `/api/version` | Версия сборки, версия растеризатора, список шрифтов с хешами |
| GET | `/api/template.xlsx` | Файл-шаблон для заполнения |
| POST | `/api/data/parse` | multipart с файлом. Ответ: `{ok, rows[], meta{as_of}, errors[], warnings[]}` |
| GET | `/api/settings/defaults` | Настройки по умолчанию |
| GET | `/api/settings/schema` | JSON Schema настроек — источник формы редактирования |
| POST | `/api/settings/validate` | Проверка загруженного JSON. Ответ: `{ok, settings, errors[], warnings[]}` |
| GET | `/api/presets` | Список доступных пресетов |
| GET | `/api/presets/{name}` | Содержимое пресета |
| GET | `/api/palette` | Утверждённая палитра. При ошибке чтения файла — встроенная, с описанием причины в ответе |
| GET | `/api/fonts` | Доступные семейства и начертания |
| POST | `/api/render/png` | `{rows, meta, settings}` → `image/png`. Используется и для превью, и для скачивания |
| POST | `/api/render/svg` | `{rows, meta, settings}` → `image/svg+xml` со встроенными шрифтами (base64 `@font-face`), заголовок на скачивание |

`/api/version` нужен, чтобы через год можно было ответить на вопрос «чем собрана картинка позапрошлого выпуска».

**Рендер-эндпоинты валидируют вход тем же кодом, что и парсер.** Фронтенд может прислать произвольные `rows` — без повторной проверки это даёт 500 вместо внятного 422.

Предупреждения к бинарному ответу едут заголовками: `X-Render-Warnings` — список сообщений в JSON, закодированный base64 (кириллица в заголовке HTTP напрямую недопустима), и `X-Required-Height` — требуемая высота в пикселях. Тело ответа остаётся чистым PNG: именно эти байты сохраняет кнопка скачивания (3.1).

Ошибки валидации возвращаются с кодом 422 и телом в едином формате: `{ok: false, errors: [{path, message}], warnings: [...]}`. Формат конверта описывается один раз и используется всеми эндпоинтами.

Отдельного эндпоинта для превью нет — превью и скачивание это один и тот же ответ `/api/render/png` (3.1).

## 10. Интерфейс

Одна страница, две колонки: слева панель управления, справа превью.

**Панель управления, сверху вниз:**

1. Загрузка файла данных, ссылка на скачивание шаблона
2. Блок сообщений валидации
3. Таблица распознанных данных и дата `as_of` — только для просмотра, служит для сверки, что файл прочитан правильно
4. Настройки оформления, сгруппированные: холст · типографика · геометрия · цвета · формат чисел · тексты · переключатели. Форма строится из JSON Schema (6.1)
5. Пресеты: выпадающий список, кнопки загрузки и сохранения JSON
6. Кнопки «Скачать PNG» и «Скачать SVG»

**Цветовое поле.** Единый контрол для всех цветов — `canvas.background`, `typography.*.color`, `colors.*`, `rowOverrides.*.*`. Образец текущего цвета открывает всплывающую панель, в которой:

- сетка образцов утверждённой палитры (6.6), у каждого — подсказка с названием и hex;
- поле ввода hex по правилам 6.6;
- системный выбор цвета (`<input type="color">`) — для случаев, когда цвет подбирают глазом.

Все три способа пишут в одно и то же поле настроек. Выбор из палитры не помечает значение особым образом: сохранённый JSON не отличает цвет, взятый из палитры, от введённого руками.

Ввод hex не дёргает отрисовку на каждый символ: запрос уходит только после того, как значение стало корректным, с тем же подавлением дребезга 250 мс.

**Превью:** полученный от бэкенда PNG, отображается с масштабированием под окно, с указанием фактического размера в пикселях и коэффициента отображения.

**Обновление превью:** запрос на бэкенд с подавлением дребезга 250 мс. Индикатор загрузки не должен вызывать мигание картинки — предыдущее превью остаётся видимым до получения нового.

**Скачивание PNG:** сохраняется байтовый массив последнего успешного превью. Повторный запрос к бэкенду не выполняется (3.1).

**Имя скачиваемого файла:** `gde-my-nahodimsya-ГГГГ-ММ-ДД.png`, дата — `as_of` с листа `meta`. Текущая дата в имени файла не используется.

## 11. Развёртывание

### 11.1. Docker

Один сервис в `docker-compose.yml`. Контейнер отдаёт и API, и собранную статику фронтенда.

```yaml
services:
  chart:
    build: .
    ports:
      - "${WDWS_PORT:-8080}:8000"
    volumes:
      - ./presets:/presets:ro
    restart: unless-stopped
    mem_limit: 512m
    healthcheck:
      test: ["CMD", "curl", "-fsS", "http://localhost:8000/api/health"]
      interval: 30s
      timeout: 3s
      retries: 3
```

Сборка образа многоступенчатая: этап сборки фронтенда, этап Python-окружения, финальный образ без инструментов сборки.

### 11.2. Сеть

Сервис слушает `0.0.0.0` внутри контейнера, порт публикуется в локальную сеть. **Исходящий доступ в интернет во время работы не требуется и не используется.** Все зависимости, шрифты и растеризатор фиксируются на этапе сборки образа.

Доступ в интернет нужен только при сборке, через имеющиеся прокси для pip, npm и Docker. Отдельного канала скачивания растеризатора не требуется: бинарник resvg вендорится в репозиторий либо тянется с внутреннего зеркала с проверкой `sha256`.

Отказ от Playwright устраняет известную проблему изолированного контура: Playwright скачивает Chromium со своего CDN, мимо прокси pip и npm, и требует либо отдельного зеркала, либо базового образа `mcr.microsoft.com/playwright/python`.

### 11.3. Безопасность

Аутентификации нет: сервис доступен всем в доверенной локальной сети. Если сеть таковой не считается, добавляется HTTP Basic на уровне обратного прокси — в объём работ по умолчанию не входит.

Загружаемые файлы не сохраняются на диск. Ограничение размера запроса — 2 МБ. Содержимое Excel обрабатывается без выполнения макросов и без вычисления формул: читаются только сохранённые значения.

### 11.4. Фиксация сборки

Требования вытекают из 1.1 и из того, что элемент выходит годами:

- Базовые образы пинятся по `sha256`-digest, не по тегу.
- Зависимости Python и JS фиксируются lock-файлами, коммитятся в репозиторий.
- Файлы шрифтов и бинарник растеризатора лежат в репозитории, их хеши проверяются при сборке.
- **Собранный образ сохраняется во внутренний реестр (или выгружается `docker save` в архив) и хранится вместе с релизом.** Рассчитывать на успешную пересборку из npm и pip через три года нельзя — это не гипотеза, а норма.

## 13. Эталонные тесты

Единственный механизм, который реально удерживает картинку от дрейфа на горизонте лет. Ручная приёмка (15) его не заменяет.

- В репозитории хранится фиксированный набор входных файлов: эталонный Excel и по одному файлу настроек на каждый пресет, плюс краевые случаи — `current == min`, `current == max`, `current == prev`, длинная подпись, сноска с переносом, восемь строк, одна строка.
- Рядом хранятся эталонные SVG и PNG для каждой комбинации.
- Тест сравнивает SVG текстом и PNG по `sha256`. Расхождение — падение сборки.
- Эталонные SVG платформу не различают и проверяются где угодно. **Хеши PNG снимаются и сверяются только внутри контейнера**: по 1.1 байты зависят от образа целиком, и на рабочей машине разработчика они другие.
- Сверка выполняется без тестовых пакетов (`scripts/update_golden.py --check`), поэтому запускается прямо в рабочем образе, а не в отдельном тестовом.
- Вся приёмка собрана в `scripts/acceptance.sh`: тесты, сборка образа, сверка эталонов, проверка работы без сети и совпадения PNG между запросами. Любая CI вызывает этот же скрипт.
- Обновление эталонов — только отдельным коммитом с явным указанием причины в сообщении и визуальной проверкой дифа.

Отдельным тестом проверяется, что при заблокированном исходящем трафике и пустом системном каталоге шрифтов результат не меняется.

**Утверждённая редакцией эталонная картинка, закоммиченная в репозиторий, является спецификацией раздела 7.** Текст фиксирует правила, но визуальный результат текстом не фиксируется.

## 15. Критерии приёмки

1. Сервис поднимается командой `docker compose up` и открывается с другой машины в локальной сети.
2. Контейнер функционирует при полностью заблокированном исходящем трафике.
3. Скачанный шаблон Excel проходит валидацию без единой ошибки после заполнения числами.
4. Файл с намеренно внесёнными дефектами — число как текст, `current` выше `max`, пропущенный столбец, дубль ключа — даёт **все** четыре сообщения за одну загрузку, каждое с адресом ячейки.
5. Файл, сохранённый скриптом и содержащий формулы без кэша, даёт сообщение про несохранённый результат формулы, а не «ячейка пуста».
6. Сохранённый JSON настроек после перезагрузки страницы и повторной загрузки даёт **побайтно идентичный** PNG.
7. PNG, сгенерированный дважды подряд из одних данных, совпадает побайтно.
8. PNG, сгенерированный из одних данных на двух разных машинах из образа с одинаковым digest, совпадает побайтно.
9. Скачанный PNG побайтно совпадает с тем, что показано в превью.
10. Значение `current`, равное `min`, и значение, равное `max`, отрисовываются с подписью, полностью помещающейся на холсте.
11. При `current`, отличающемся от `prev` на величину меньше суммы радиусов, точки не сливаются в нечитаемое пятно, соединительная линия отсутствует.
12. При `current == prev` кольцо «неделю назад» отчётливо видно поверх текущей точки.
13. Подпись строки длиной 40 символов на кириллице даёт предупреждение о переполнении колонки, а не молча наезжает на шкалу.
14. Сноска длиннее ширины холста переносится по словам и полностью помещается на картинке.
15. В схеме настроек отсутствует возможность скрыть точку «неделю назад».
16. Полоса шкалы не содержит градиентов и цветового кодирования ни при каких значениях настроек.
17. В сгенерированном SVG отсутствует `<foreignObject>`.
18. Загрузка JSON с полем `version`, отличным от поддерживаемого, приводит к понятному сообщению, а не к ошибке сервера.
19. Дата в строке источника и в имени файла берётся с листа `meta`; при удалении листа выдаётся ошибка, а не подстановка сегодняшней даты.
20. Эталонные тесты (13) проходят в CI.
21. Цвет задаётся тремя способами — образцом палитры, вводом hex и системным выбором; все три дают неразличимый результат в сохранённом JSON.
22. Ввод `378add`, `#378ADD` и `#3AD` принимается и нормализуется к `#RRGGBB` в верхнем регистре; `#378AD`, `red` и `#378ADDFF` отклоняются, при этом превью не ломается и сохраняет прежний цвет.
23. При отсутствующем или повреждённом `palette.json` сервис поднимается, UI показывает встроенную палитру и предупреждение.
24. Подмена `palette.json` не меняет PNG, собранный из неизменных файлов данных и настроек.
25. Совпадающие `colors.current` и `colors.prev` дают предупреждение о неразличимости, но не блокируют отрисовку.

## 17. Замечание к регламенту публикации

Вне объёма разработки, но существенно для результата: **картинку следует отправлять в Telegram файлом, а не фотографией.** Фотографии пережимаются и уменьшаются по длинной стороне, из-за чего вся работа по детерминированному рендерингу теряет смысл на последнем шаге.
